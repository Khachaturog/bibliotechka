# Исправление ошибки 404 для API

## Проблема
При обращении к `https://bibliotechka.online/api/v1/groups/list` получаете ошибку 404.

## Решение

Проблема решена созданием структуры файлов и настройкой `.htaccess` для правильного роутинга.

### Текущая структура файлов API

```
api/
├── config.php              # Конфигурация БД
├── index.php               # Fallback роутер
└── v1/
    ├── groups/
    │   ├── list.php        # GET /api/v1/groups/list
    │   └── index.php       # GET /api/v1/groups?slug=...
    ├── data/
    │   ├── list.php        # GET /api/v1/data/list
    │   ├── index.php       # GET /api/v1/data?slug=...
    │   └── authors.php     # GET /api/v1/data/{slug}/authors
    └── subgroups/
        └── index.php       # GET /api/v1/subgroups
```

### Важные моменты

1. **Корневой `.htaccess`** содержит правила роутинга для API
2. **В папке `api/` НЕ должно быть `.htaccess`** - это может конфликтовать
3. Все файлы должны быть в правильных папках с правильными именами

### Шаг 2: Проверьте работу API

После загрузки файлов проверьте в браузере:

1. **Группы**: `https://bibliotechka.online/api/v1/groups/list`
   - Должен вернуть JSON с группами

2. **Группа по slug**: `https://bibliotechka.online/api/v1/groups?slug=skill`
   - Должен вернуть JSON с одной группой

3. **Карточки**: `https://bibliotechka.online/api/v1/data/list?status_slug=published`
   - Должен вернуть JSON с карточками

4. **Карточка по slug**: `https://bibliotechka.online/api/v1/data?slug=001`
   - Должен вернуть JSON с одной карточкой

5. **Авторы карточки**: `https://bibliotechka.online/api/v1/data/001/authors`
   - Должен вернуть JSON с авторами

6. **Подгруппы**: `https://bibliotechka.online/api/v1/subgroups`
   - Должен вернуть JSON с подгруппами

### Шаг 3: Проверьте подключение к БД

Если API все еще не работает, проверьте подключение к базе данных:

1. **Создайте временный файл** `api/test-connection.php` (см. пример в [DIAGNOSTICS.md](DIAGNOSTICS.md))
2. **Загрузите на сервер**
3. **Откройте в браузере**: `https://bibliotechka.online/api/test-connection.php`
4. **Проверьте результаты**:
   - Если видите ошибку подключения → см. ниже "Доступ к БД"
   - Если подключение успешно, но таблицы пустые → импортируйте данные

**⚠️ ВАЖНО:** После проверки удалите `api/test-connection.php` из соображений безопасности!

### Шаг 4: Настройка доступа к БД (если нужно)

Если `test-connection.php` показывает ошибку подключения:

1. **Узнайте IP-адрес вашего веб-сервера**:
   - В панели управления хостингом найдите информацию о сервере
   - Или обратитесь в поддержку

2. **Добавьте IP в список разрешенных для MySQL**:

   - **НЕ добавляйте `*` или `0.0.0.0/0`** - это небезопасно!

## Проверка `.htaccess`

Убедитесь, что корневой `.htaccess` содержит правила для роутинга API:

1. **Проверьте наличие файла** `.htaccess` в корне проекта
2. **Убедитесь, что в папке `api/` НЕТ `.htaccess`** - это может конфликтовать
3. **Проверьте, что включен mod_rewrite** в Apache (обычно включен по умолчанию)
4. **Проверьте правила роутинга** в `.htaccess`:
   - Должны быть правила для `/api/v1/{resource}/list`
   - Должны быть правила для `/api/v1/{resource}/{slug}/authors`
   - Должны быть правила для `/api/v1/{resource}`

Если проблемы продолжаются, обратитесь в поддержку хостинга для проверки настроек Apache.

## Проверка после исправления

После загрузки файлов:

1. Откройте главную страницу сайта
2. Откройте консоль браузера (F12 → Console)
3. Проверьте, что нет ошибок загрузки данных
4. Проверьте вкладку Network - запросы к API должны возвращать статус 200

## Если проблема не решена

Соберите информацию:
- Скриншоты консоли браузера
- Скриншоты Network tab
- Результаты `test-connection.php`
- Логи ошибок с сервера (если доступны)

Обратитесь в поддержку хостинга или к разработчику.
