# Проверка файлов на сервере

## Проблема: 404 ошибки для API

Если вы видите ошибки 404 для API эндпоинтов, проверьте следующее:

## 1. Проверьте структуру файлов на сервере

Убедитесь, что на сервере есть следующие файлы:

```
api/
├── config.php
├── index.php
├── v1/
│   ├── groups/
│   │   ├── list.php          ← ДОЛЖЕН БЫТЬ
│   │   └── index.php         ← ДОЛЖЕН БЫТЬ
│   ├── data/
│   │   ├── list.php          ← ДОЛЖЕН БЫТЬ
│   │   ├── index.php         ← ДОЛЖЕН БЫТЬ
│   │   └── authors.php       ← ДОЛЖЕН БЫТЬ
│   ├── subgroups/
│   │   └── index.php         ← ДОЛЖЕН БЫТЬ
│   ├── subgroups.php         ← ДОЛЖЕН БЫТЬ (альтернатива)
│   ├── groups.php
│   └── data.php
└── .htaccess                 ← ДОЛЖЕН БЫТЬ
```

## 2. Проверьте права доступа к файлам

Файлы должны быть доступны для чтения:
- Файлы: права `644` или `755`
- Папки: права `755`

Если используете FTP/SFTP клиент:
- Выберите все файлы → Права доступа → `644` для файлов, `755` для папок

## 3. Проверьте .htaccess

Убедитесь, что файл `.htaccess` загружен в корень сайта и содержит правильные настройки.

## 4. Проверьте работу API напрямую

Откройте в браузере (замените на ваш домен):

1. **Группы**: `https://bibliotechka.online/api/v1/groups/list`
   - Должен вернуть JSON с группами
   - Если 404 → файл `api/v1/groups/list.php` не найден

2. **Карточки**: `https://bibliotechka.online/api/v1/data/list?status_slug=published`
   - Должен вернуть JSON с карточками
   - Если 404 → файл `api/v1/data/list.php` не найден

3. **Подгруппы**: `https://bibliotechka.online/api/v1/subgroups`
   - Должен вернуть JSON с подгруппами
   - Если 404 → файл `api/v1/subgroups.php` или `api/v1/subgroups/index.php` не найден

## 5. Если файлы есть, но все равно 404

### Вариант A: Apache не обрабатывает .htaccess

Проверьте, включен ли mod_rewrite:
- Обратитесь в поддержку хостинга "Джино"
- Спросите, включен ли mod_rewrite для вашего аккаунта

### Вариант B: Используйте прямые пути к файлам

Если `.htaccess` не работает, можно использовать прямые пути:

1. Откройте `js/config.js`
2. Измените `API_BASE` на прямые пути к файлам:

```javascript
API_BASE: '/api/v1',
getApiUrl: function(endpoint, params = {}) {
    // Для subgroups используем прямой путь
    if (endpoint === 'subgroups') {
        const queryString = new URLSearchParams(params).toString();
        return `/api/v1/subgroups.php${queryString ? '?' + queryString : ''}`;
    }
    // Для остальных используем стандартный путь
    const queryString = new URLSearchParams(params).toString();
    return `${this.API_BASE}/${endpoint}${queryString ? '?' + queryString : ''}`;
},
```

Но это не рекомендуется - лучше исправить проблему с файлами или .htaccess.

## 6. Проверка через test-connection.php

1. Загрузите `api/test-connection.php` на сервер
2. Откройте: `https://bibliotechka.online/api/test-connection.php`
3. Проверьте результаты:
   - Если видите данные → БД работает, проблема в файлах API
   - Если ошибка БД → см. инструкцию по настройке доступа к БД

## 7. Решение проблемы Mixed Content

Ошибка "Mixed Content" означает, что где-то используется HTTP вместо HTTPS или относительных путей.

Проверьте:
- Все пути к API должны быть относительными: `/api/v1/...`
- Не должно быть полных URL с `http://` или `https://` (кроме внешних ссылок)

В вашем коде используется `window.CONFIG?.getApiUrl()`, который возвращает относительные пути - это правильно.

Если ошибка все еще есть, возможно браузер кэширует старую версию. Очистите кэш браузера (Ctrl+Shift+R или Cmd+Shift+R).

## Быстрое решение

Если нужно быстро исправить, загрузите все файлы из папки `api/v1/` на сервер, убедившись, что структура папок сохранена.
