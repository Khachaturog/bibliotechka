# Правила разработки проекта

— Сначала предложи решение, потом получи моё согласие на изменение кода
— При миграции баз данных обязательно проверяй, чтобы стоял запрет на удаление данных в БД

### Правила работы с миграциями БД

— **Обязательно создавать бэкап** перед применением любой миграции
  - Размер бэкапа должен быть сохранен для проверки
  - Проверять, что бэкап не пустой (размер > 0)

— **Проверять количество записей до и после миграции** — должно быть идентично во всех таблицах
  - Использовать скрипт `scripts/check-migration-safety.sh before/after/compare`
  - Если количество записей изменилось — это ошибка, нужно откатить миграцию

— **Проверять размер бэкапа до и после создания** — размер файла бэкапа не должен изменяться
  - Размер бэкапа сохраняется в файл `.size` рядом с бэкапом
  - При сравнении размер должен совпадать (каждый байт)

— **Если количество записей изменилось после миграции** — это критическая ошибка:
  1. Немедленно откатить миграцию
  2. Проверить миграцию на наличие операций DELETE, DROP TABLE, TRUNCATE
  3. Исправить миграцию и повторить процесс

— **После успешной миграции** сохранять информацию:
  - Путь к бэкапу
  - Размер бэкапа
  - Результаты проверок (до/после сравнение)
  - Дата и время применения миграции

### Технические компетенции
- При разработке использовать экспертные знания и лучшие практики в:
  - **HTML**: семантическая разметка, доступность (accessibility), SEO-оптимизация
  - **CSS**: современные возможности (CSS Grid, Flexbox, Custom Properties), адаптивный дизайн, производительность
  - **JavaScript**: современный ES6+ синтаксис, модульная архитектура, работа с API, обработка ошибок
  - **PHP**: безопасность (подготовленные запросы, валидация), архитектура кода, работа с базой данных, REST API

## Заметки
- Придерживаться принципа "сначала функциональность, потом красота"
- Постоянно документировать изменения
- Регулярно проверять кроссбраузерность
