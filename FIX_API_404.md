# Исправление ошибки 404 для API

## Проблема
При обращении к `https://bibliotechka.online/api/v1/groups/list` получаете ошибку 404.

## Решение

Я создал прямые файлы для обработки API запросов, которые будут работать без mod_rewrite.

### Шаг 1: Загрузите новые файлы на сервер

Загрузите следующие файлы в соответствующие папки:

```
api/v1/groups/list.php          → api/v1/groups/list.php
api/v1/groups/index.php         → api/v1/groups/index.php
api/v1/data/list.php            → api/v1/data/list.php
api/v1/data/index.php           → api/v1/data/index.php
api/v1/data/authors.php         → api/v1/data/authors.php
api/v1/subgroups/index.php      → api/v1/subgroups/index.php
```

### Шаг 2: Проверьте работу API

После загрузки файлов проверьте в браузере:

1. **Группы**: `https://bibliotechka.online/api/v1/groups/list`
   - Должен вернуть JSON с группами

2. **Карточки**: `https://bibliotechka.online/api/v1/data/list?status_slug=published`
   - Должен вернуть JSON с карточками

3. **Подгруппы**: `https://bibliotechka.online/api/v1/subgroups`
   - Должен вернуть JSON с подгруппами

### Шаг 3: Проверьте подключение к БД

Если API все еще не работает, проверьте подключение к базе данных:

1. Загрузите файл `api/test-connection.php` на сервер
2. Откройте в браузере: `https://bibliotechka.online/api/test-connection.php`
3. Проверьте результаты:
   - Если видите ошибку подключения → см. ниже "Доступ к БД"
   - Если подключение успешно, но таблицы пустые → импортируйте данные

### Шаг 4: Настройка доступа к БД (если нужно)

Если `test-connection.php` показывает ошибку подключения:

1. **Узнайте IP-адрес вашего веб-сервера**:
   - В панели управления хостингом найдите информацию о сервере
   - Или обратитесь в поддержку

2. **Добавьте IP в список разрешенных для MySQL**:
   - В панели управления MySQL → "Доступ по IP"
   - Добавьте IP вашего веб-сервера (например: `45.92.174.185`)
   - **НЕ добавляйте `*` или `0.0.0.0/0`** - это небезопасно!

3. **Проверьте настройки в `api/config.php`**:
   ```php
   define('DB_HOST', 'mysql.35401aca832c.hosting.myjino.ru');
   define('DB_USER', 'j35045845_biblio');
   define('DB_PASSWORD', 'tuhrih-zoqmYp');
   define('DB_NAME', 'j35045845_biblio');
   ```
   - Убедитесь, что эти данные правильные

### Шаг 5: Удалите тестовый файл

**ВАЖНО**: После проверки удалите файл `api/test-connection.php` из соображений безопасности!

## Альтернативное решение (если прямые файлы не работают)

Если прямые файлы не работают, возможно нужно настроить `.htaccess`. Проверьте:

1. Включен ли mod_rewrite в Apache (обычно включен по умолчанию)
2. Правильно ли загружен файл `.htaccess` в корень сайта
3. Обратитесь в поддержку хостинга "Джино" для проверки настроек

## Проверка после исправления

После загрузки файлов:

1. Откройте главную страницу сайта
2. Откройте консоль браузера (F12 → Console)
3. Проверьте, что нет ошибок загрузки данных
4. Проверьте вкладку Network - запросы к API должны возвращать статус 200

## Если проблема не решена

Соберите информацию:
- Скриншоты консоли браузера
- Скриншоты Network tab
- Результаты `test-connection.php`
- Логи ошибок с сервера (если доступны)

Обратитесь в поддержку хостинга или к разработчику.
