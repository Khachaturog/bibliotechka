# Чек-лист для безопасного применения миграций

## 📋 Обязательные шаги перед применением миграции:

### 1. Создание бэкапа ✅

**Обязательно создать бэкап перед любой миграцией!**

```bash
# Использовать скрипт для конкретной миграции
./scripts/create-backup-015.sh

# Или универсальный скрипт
./scripts/create-backup.sh
```

**Проверить, что бэкап создан:**
```bash
ls -lh backups/backup_before_migration_*.sql
```

Бэкап должен быть не пустым (размер > 0).

### 2. Сохранение статистики ДО миграции ✅

**Перед применением миграции сохранить статистику:**

```bash
./scripts/check-migration-safety.sh before
```

Это сохранит количество записей в каждой таблице для последующего сравнения.

### 3. Применение миграции

```bash
# Использовать скрипт миграции (автоматически включает проверки)
./scripts/run-migration-015.sh

# Или вручную
mysql -h HOST -u USER -p DATABASE < 015_*.sql
```

### 4. Проверка статистики ПОСЛЕ миграции ✅

**После применения миграции проверить статистику:**

```bash
./scripts/check-migration-safety.sh after
```

### 5. Сравнение результатов ✅

**Сравнить статистику до и после:**

```bash
./scripts/check-migration-safety.sh compare
```

**Ожидаемый результат:**
- ✅ Все таблицы должны иметь одинаковое количество записей
- ✅ Различий быть не должно
- ❌ Если обнаружены различия — **ОБЯЗАТЕЛЬНО ОТКАТИТЬ миграцию**

### 6. Проверка размера файлов БД (опционально)

Можно проверить общий размер базы данных:

```sql
SELECT 
    TABLE_NAME,
    ROUND((DATA_LENGTH + INDEX_LENGTH) / 1024 / 1024, 2) AS 'Size (MB)'
FROM information_schema.TABLES 
WHERE TABLE_SCHEMA = 'j35045845_biblio'
ORDER BY (DATA_LENGTH + INDEX_LENGTH) DESC;
```

**Примечание:** Размер может немного измениться из-за изменения структуры таблиц (NULL/NOT NULL), но количество записей должно остаться неизменным.

## ❌ Что делать, если обнаружены различия:

1. **Немедленно откатить миграцию:**
   ```bash
   mysql -h HOST -u USER -p DATABASE < backups/backup_before_migration_*.sql
   ```

2. **Проверить миграцию:**
   - Убедиться, что нет операций DELETE, DROP TABLE, TRUNCATE
   - Проверить, что все операции безопасны

3. **Исправить миграцию** и повторить процесс с самого начала

## 📝 Правила (из [docs/SAFETY_AND_RULES.md](docs/SAFETY_AND_RULES.md)):

- **Обязательно создавать бэкап** перед применением любой миграции
- **Проверять количество записей до и после миграции** — должно быть идентично
- **Проверять размер файлов БД до и после миграции** — должен совпадать (каждый бит)
- Если количество записей или размер изменился — это ошибка, нужно откатить миграцию
- После успешной миграции сохранять информацию о бэкапе и результатах проверок

## 🔄 Полный процесс (пример):

```bash
# 1. Создать бэкап
./scripts/create-backup-015.sh

# 2. Проверить ДО
./scripts/check-migration-safety.sh before

# 3. Применить миграцию
./scripts/run-migration-015.sh

# 4. Скрипт автоматически проверит ПОСЛЕ и сравнит

# 5. Если что-то не так - откатить
mysql -h HOST -u USER -p DATABASE < backups/backup_before_migration_015_*.sql
```

## 📌 Миграция 016: Синхронизация card_authors

**Особенность:** Эта миграция добавляет записи (не изменяет структуру), поэтому количество записей должно увеличиться с 715 до 723.

### Процесс для миграции 016:

```bash
# Вариант 1: Использовать готовый SQL файл с бэкапом (рекомендуется)
# Файл: 016_sync_with_backup.sql (в этой папке)
# Включает: бэкап + миграция + проверка

# Выполнить через phpMyAdmin или MySQL клиент:
mysql -h HOST -u USER -p DATABASE < 016_sync_with_backup.sql

# Вариант 2: Использовать скрипт (если доступен MySQL клиент)
./scripts/run-migration-016.sh

# Проверка результата:
# Должно быть: 723 записи в card_authors
SELECT COUNT(*) FROM card_authors;  -- Ожидается: 723
```

**Ожидаемый результат:**
- ✅ Бэкап создан: `card_authors_backup_20251223` (715 записей)
- ✅ Миграция выполнена: `card_authors` (723 записи)
- ✅ Добавлено 8 недостающих записей
